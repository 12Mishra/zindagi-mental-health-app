# Zindagi Voice Server (Go)

A Go-based backend service that powers the voice conversation feature in the Zindagi mental health app. It runs alongside the existing Express.js auth server and handles the complete voice pipeline: **Speech-to-Text → AI Response → Text-to-Speech**.

---

## What Is This?

This is a standalone Go HTTP server that:

1. **Receives audio** from the mobile app (recorded via the phone's microphone)
2. **Transcribes it** using Deepgram's Speech-to-Text API (nova-3 model)
3. **Generates an AI response** using Google's Gemini LLM (as "Lisa", a mental health companion)
4. **Converts the response to speech** using Deepgram's Text-to-Speech API (Aura thalia voice)
5. **Stores everything** in a PostgreSQL database (the same Neon database the Express server uses)
6. **Returns** the transcript, AI response text, and a URL to play the TTS audio

```
Mobile App                          Go Server (:4001)                    External APIs
┌─────────────┐                    ┌────────────────────┐              ┌──────────────┐
│ Record audio │──POST /voice/msg──▶│ 1. Receive audio    │              │              │
│ (expo-av)    │                    │ 2. Deepgram STT ────┼─────────────▶│ Deepgram API │
│              │                    │ 3. Gemini LLM  ─────┼─────────────▶│ Gemini API   │
│ Play TTS     │◀─GET /voice/audio──│ 4. Deepgram TTS ────┼─────────────▶│ Deepgram API │
│ (expo-av)    │                    │ 5. Store in Postgres│              │              │
│              │                    │ 6. Return response  │              └──────────────┘
│ Chat UI      │◀─GET /voice/msgs───│                     │
└─────────────┘                    └─────────────────────┘
```

## Architecture

### Why Go?

The existing backend is in Express.js (TypeScript) and handles authentication only. We chose Go for the voice service because:

- **Performance**: Go handles concurrent requests efficiently with goroutines
- **Low latency**: Important for real-time voice interactions
- **Deepgram SDK**: Deepgram has an official Go SDK
- **Separation of concerns**: Voice processing is a distinct responsibility from auth

### Why a Separate Server?

The Go voice server runs on **port 4001** while the Express auth server runs on **port 4000**. Both connect to the **same PostgreSQL database**. This design:

- Keeps the existing auth system untouched
- Allows independent scaling of voice processing
- Uses the same session tokens for authentication

## How Each Component Works

### 1. Config (`config/config.go`)

Loads environment variables from `.env` using the `godotenv` library:

```go
type Config struct {
    DatabaseURL    string  // PostgreSQL connection string (Neon)
    Port           string  // Server port (default: 4001)
    DeepgramAPIKey string  // Deepgram API key for STT/TTS
    GeminiAPIKey   string  // Google Gemini API key for LLM
}
```

### 2. Database (`db/db.go`)

**Connection**: Uses `pgx` (PostgreSQL driver for Go) to create a connection pool.

**Auto-migration**: On startup, creates the `Conversation` and `Message` tables if they don't exist. This runs every time the server starts — it's safe because it uses `CREATE TABLE IF NOT EXISTS`.

**Tables created**:

| Table | Purpose |
|-------|---------|
| `Conversation` | Groups messages into a session. Has userId, moods, timestamps |
| `Message` | Individual messages. Has role (USER/ASSISTANT), content, audioUrl |

Both tables use UUID primary keys generated by PostgreSQL's `gen_random_uuid()`.

### 3. Auth Middleware (`middleware/auth.go`)

Validates bearer tokens against the existing `Session` table (created by the Express auth system):

1. Extracts `Authorization: Bearer <token>` header
2. SHA-256 hashes the token (same algorithm as Express auth)
3. Queries the `Session` table: checks `tokenHash` matches, `revokedAt IS NULL`, `expiresAt > now`
4. Atomically updates `lastSeenAt` (session refresh)
5. Stores `userId` in the request context for handlers to use

This means the mobile app uses the **same session token** for both the Express auth endpoints and the Go voice endpoints.

### 4. CORS Middleware (`middleware/cors.go`)

Allows the mobile app (running on a different origin) to access the API:

- `Access-Control-Allow-Origin: *` (allows all origins)
- `Access-Control-Allow-Methods: GET, POST, OPTIONS`
- `Access-Control-Allow-Headers: Content-Type, Authorization`
- Handles OPTIONS preflight requests

### 5. Deepgram Service (`services/deepgram.go`)

Two functions using the Deepgram REST API directly (not the SDK, for simplicity):

#### `TranscribeAudio(ctx, audioData []byte) (string, error)`
- Sends audio bytes to `POST https://api.deepgram.com/v1/listen`
- Uses `nova-3` model with `smart_format=true`
- Returns the transcript text

#### `SynthesizeSpeech(ctx, text string) ([]byte, error)`
- Sends text to `POST https://api.deepgram.com/v1/speak`
- Uses `aura-2-thalia-en` model (warm, natural female voice)
- Returns MP3 audio bytes

### 6. Gemini Service (`services/gemini.go`)

Uses the Google Generative AI Go SDK (`google.golang.org/genai`):

#### `GenerateResponse(ctx, history, userMessage, moods) (string, error)`
- Creates a Gemini client with `gemini-2.5-flash` model
- Passes a system prompt that defines "Lisa" — a warm, empathetic mental health companion
- Includes conversation history for context
- Includes mood context from the check-in screen
- Returns a short response (2-3 sentences, suitable for TTS)

**Lisa's System Prompt** positions her as:
- A warm, non-judgmental companion for Indian college students
- Keeps responses SHORT (for TTS playback)
- References the user's mood when relevant
- Never provides medical diagnoses
- Suggests crisis support hotlines if the user expresses distress

### 7. Voice Orchestration Service (`services/voice.go`)

The core pipeline that ties everything together:

#### `StartConversation(ctx, userID, moods) (string, error)`
- Creates a new `Conversation` record in the database
- Stores the user's selected moods for context
- Returns the conversation ID

#### `ProcessVoiceMessage(ctx, userID, conversationID, audioData) (*VoiceResponse, error)`

This is the main pipeline:

```
Step 1: Verify conversation belongs to user (security check)
Step 2: Deepgram STT → transcript text
Step 3: Store USER message in database
Step 4: Fetch conversation history for context
Step 5: Get moods from conversation record
Step 6: Gemini LLM → Lisa's response text
Step 7: Store ASSISTANT message in database
Step 8: Deepgram TTS → MP3 audio bytes
Step 9: Save audio file to uploads/audio/{messageId}.mp3
Step 10: Update message record with audio URL
Step 11: Return VoiceResponse with both messages
```

If TTS fails, it's non-fatal — the response is still returned without audio.

#### `GetMessages(ctx, conversationID) ([]Message, error)`
- Fetches all messages for a conversation, ordered by creation time
- Returns empty array (not nil) if no messages exist

### 8. HTTP Handlers (`handlers/voice.go`)

Four endpoints:

#### `POST /voice/conversation` (authenticated)
**Request**: `{ "moods": ["anxious", "sad"] }`
**Response**: `{ "conversationId": "uuid-here" }`
**What it does**: Creates a new conversation with mood context

#### `POST /voice/message` (authenticated)
**Request**: `multipart/form-data` with:
- `audio` — the recorded audio file (m4a/aac)
- `conversationId` — which conversation to add the message to

**Response**:
```json
{
  "userMessage": {
    "id": "...",
    "conversationId": "...",
    "role": "USER",
    "content": "I've been feeling really stressed about exams"
  },
  "assistantMessage": {
    "id": "...",
    "conversationId": "...",
    "role": "ASSISTANT",
    "content": "I hear you. Exam pressure can feel overwhelming. What's been weighing on you the most?",
    "audioUrl": "/voice/audio/uuid-here"
  }
}
```

**What it does**: Runs the full STT → LLM → TTS pipeline

#### `GET /voice/messages?conversationId=...` (authenticated)
**Response**: `{ "messages": [...] }`
**What it does**: Returns all messages in a conversation

#### `GET /voice/audio/{messageID}` (authenticated)
**Response**: MP3 audio file with `Content-Type: audio/mpeg`
**What it does**: Serves the TTS audio file for a message

### 9. Main Entry Point (`main.go`)

Wires everything together:

1. Loads config from `.env`
2. Connects to PostgreSQL (Neon)
3. Runs auto-migration (creates tables if needed)
4. Initializes Deepgram and Gemini services
5. Creates the upload directory for audio files
6. Sets up chi router with CORS middleware
7. Registers routes:
   - `GET /health` — health check (no auth)
   - `/voice/*` — all voice routes (with auth middleware)
8. Starts listening on port 4001

## The `zindagi-voice.exe` File

This is the **compiled Go binary** — the executable version of the server. It's created when you run:

```bash
go build .
```

or when `go run .` compiles and executes in one step.

**What it is**: A single self-contained executable that includes:
- The Go runtime
- All your application code
- All dependencies (chi, pgx, Deepgram SDK, Gemini SDK)

**How to use it**:
```bash
# Direct execution (doesn't need Go installed)
./zindagi-voice.exe

# Or use go run (compiles + runs)
go run .
```

**When to use the .exe**:
- Production deployment (copy just the .exe + .env)
- When you don't want to recompile every time
- Sharing with someone who doesn't have Go installed

**When to use `go run .`**:
- Development (recompiles on every run, so you always run the latest code)

The `.exe` is in `.gitignore` and should not be committed to version control.

## Database Schema

### Conversation Table

```sql
CREATE TABLE "Conversation" (
    "id"        TEXT PRIMARY KEY DEFAULT gen_random_uuid()::text,
    "userId"    TEXT NOT NULL REFERENCES "User"(id) ON DELETE CASCADE,
    "moods"     TEXT[] DEFAULT '{}',
    "startedAt" TIMESTAMP DEFAULT now(),
    "endedAt"   TIMESTAMP
);
```

| Column | Type | Description |
|--------|------|-------------|
| id | TEXT (UUID) | Primary key |
| userId | TEXT | References User table (from Express auth) |
| moods | TEXT[] | Mood selections from check-in screen |
| startedAt | TIMESTAMP | When the conversation started |
| endedAt | TIMESTAMP | When the conversation ended (nullable) |

### Message Table

```sql
CREATE TABLE "Message" (
    "id"             TEXT PRIMARY KEY DEFAULT gen_random_uuid()::text,
    "conversationId" TEXT NOT NULL REFERENCES "Conversation"(id) ON DELETE CASCADE,
    "role"           TEXT NOT NULL CHECK (role IN ('USER', 'ASSISTANT')),
    "content"        TEXT NOT NULL,
    "audioUrl"       TEXT,
    "createdAt"      TIMESTAMP DEFAULT now()
);
```

| Column | Type | Description |
|--------|------|-------------|
| id | TEXT (UUID) | Primary key |
| conversationId | TEXT | References Conversation table |
| role | TEXT | "USER" or "ASSISTANT" |
| content | TEXT | The message text |
| audioUrl | TEXT | Path to TTS audio file (only for ASSISTANT messages) |
| createdAt | TIMESTAMP | When the message was created |

## Environment Variables

Create a `.env` file in the `server/go-voice/` directory:

```env
DATABASE_URL=postgresql://user:pass@host:5432/dbname?sslmode=require
DEEPGRAM_API_KEY=your_deepgram_api_key_here
GEMINI_API_KEY=your_gemini_api_key_here
PORT=4001
```

| Variable | Required | Default | Description |
|----------|----------|---------|-------------|
| DATABASE_URL | Yes | — | PostgreSQL connection string |
| DEEPGRAM_API_KEY | Yes | — | Deepgram API key (get from deepgram.com) |
| GEMINI_API_KEY | Yes | — | Google Gemini API key (get from aistudio.google.com) |
| PORT | No | 4001 | Port the server listens on |

## Running the Server

```bash
# Navigate to the directory
cd server/go-voice

# Option 1: Run with go run (compiles + runs)
go run .

# Option 2: Build then run the binary
go build .
./zindagi-voice.exe    # Windows
./zindagi-voice        # Mac/Linux

# The server will start on port 4001
# You'll see: "Voice server listening on :4001"
```

```bash
# Health check
```
